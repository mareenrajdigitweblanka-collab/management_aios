# Review Summary "Download PDF" — filenames-only export: validation check

Date: 2026-09-30
Branch: `feature/review-summary-attachments`
Status: LOCAL VALIDATION ONLY. Browser and deployed (Preview) testing has NOT been performed.

## Requirement

1. "Download PDF" downloads the review summary PDF with attachment filenames as a list
   ("No attachments" when there are none) — no attachment contents or pages.
2. "Download all reviews as one PDF" keeps its current behaviour, including attachment handling.

## Root cause

`GET /api/staff-review-summaries/export/pdf` (Download PDF) was extended by the attachments
feature to fetch every attachment's bytes and append PDF pages and Word/Excel conversions —
the same steps `GET /export/pdf/history` (Download all reviews as one PDF) performs. Both
buttons therefore produced attachment-embedded PDFs. Frontend handlers were already calling
the correct routes and are unchanged.

## Change (files)

- `backend/review_summary_pdf_export.py` — `build_review_summary_pdf(..., attachments_filenames_only=False)`;
  new filename-list renderer (XML-escaped, wrap-anywhere style, 200-char cut, "No attachments").
  Default behaviour unchanged.
- `backend/routers/staff_review_summaries.py` — `_attachment_export_dict` / `_build_pdf_ready_records`
  gain `include_content` (default True). `/export/pdf` passes False (no storage download) and no
  longer appends attachment pages. `/export/pdf/history` and `/export/zip` unchanged.
- `backend/tests/test_review_summary_attachments.py` — 5 tests that asserted the old embedding on
  `/export/pdf` replaced with: multi-attachment filenames-only (1 page, zero storage downloads),
  no attachments, long/special-character filenames; plus a history test proving contents are
  still embedded on `/export/pdf/history`.

Not changed: database schema, stored attachments, authentication/authorization, response
filenames, environment variables, deployment configuration, frontend code.
